## Exact reproduction order
All commands below run from `soc-stage8/` (submission root), with the venv activated.
### Full clean rebuild and test, unattended, from zero
commands: `make clean` && `make provision` && `make test`
1. `make clean` - for a clean-state rebuild.
2. `make provision  - `pip install pytest --break-system-packages`
3. Place `windows-replay.jsonl` in `raw-events/`; verify its sha256 matches `raw-events/source-manifest.json` before proceeding
4. `python3 -m pytest tests/ -v` — expect 30 passed
5. `python3 -m pipeline.cli run --input raw-events/windows-replay.jsonl` — expect 90 verdicts, 12 alerted, 78 suppressed, hash `fa9cd4f6778c16a9d8bba6a1204ee483d5482ef84ad6104376667de1b74b4d57`
6. python3 -m pytest tests/test_mutation_table.py tests/test_mutation_harness.py -v — expect 4 passed: 42/42 per-technique mutation checks pass, 8/8 harness
mutations run with >=6 alerting and 0/12 benign holdouts flipped by mutation
- python3 generate_report.py - generate mutation-test-report.csv
7. `python3 -m pipeline.harness --fixtures fixtures/public-fixtures.json --junit-out regression-results.xml --json-out harness-report.json` — expect 33/36 passed, exit code 1 (the 3 known/documented failures, not a bug — see `decision-log.md` D-008) 

## Detection contract summary
- All 12 `technique-matrix.csv` rows implemented (`pipeline/rules/`)
- 6 of 12 are genuine correlation/sequence rules (`T1053.005`, `T1087.001`, `T1057`, `T1136.001`, `T1555`, `T1027`), meeting the brief's minimum of 6
- 6 replay-covered rules (`T1059.001`, `T1105`, `T1547.001`, `T1059.003`, `T1218.011`, `T1003.001`) validated with exact-match, 0 false positive / 0 false negative results against real sealed-replay ground truth
- 6 self-constructed rules (no real telemetry exists for these techniques anywhere in the sealed evidence) validated against documented synthetic fixtures — see `fixtures/synthetic/provenance.md`
- No rule reads `command_line`, `command_family`, `mitre_technique`, or `marker` — all four are either unusable (scrubbed) or explicitly prohibited detection constants; see `decision-log.md` 
- Mutation robustness proven at two levels: 
(1) per-technique table — one field-loss, rename, encoding, parent-process, or timing mutation documented for all 12 techniques (42 checks total); 
(2) harness-level acceptance bucket — 8 semantic attack mutations, 6 of which must still alert (proving invariance to command-line/command-family content, which no rule reads) and 2 of which are documented misses (proving a named rename blind spot actually reproduces, not just claimed). 0 of 12 benign holdouts alert under the same mutation. Both levels pass.

Sysmon/Atomic Red Team work, retained per the programme's compatibility-adapter allowance.

for the equivalent evidence instead.

## Known limitations
Documented in full in `assessment-manifest.json`'s
`known_limitations` and `coverage-matrix.csv`'s 
per-rule blind-spot column for the full list. 
Items: 
- 3 of 36 public fixtures (P-DET-14, P-DET-33, P-DET-34) produce unexpected_alert -- provably unsolvable with permitted signal, see decision-log.md D-008",
- 6 of 12 rules (self-constructed techniques) have no real ground truth to validate against -- tested only against self-built synthetic fixtures with documented provenance
- 2 of the 8 harness-level mutations (T1053.005, T1136.001) are designed not to alert — they reproduce each rule's own documented static-allowlist rename blind spot. This is the honest floor of a schema with no usable command-line field, not an oversight.
